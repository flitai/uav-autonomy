## 2. 标准命令与运行约定

从仓库根目录执行以下命令；入口通过自身位置定位项目，支持其他工作目录及中文空格路径。解释器参数应替换为本机已验证路径，下例沿用本轮安装布局。

```powershell
$pythonExe = Join-Path $env:LOCALAPPDATA 'Python/pythoncore-3.14-64/python.exe'
# 自动编排 GUI、无界面、隔离路径、重复运行和故障检查。

# 仅取得本轮真实 GUI 人工确认后执行；不会重新发布 AMASE。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\windows\amase-tcp.tests.ps1 -Action Finalize -ValidationRunId '<VALIDATION_RUN_ID>' -ManualConfirmation '<实际确认内容>' -PythonExecutable $pythonExe
```

Automatic 复用既有 run-amase.ps1 和正式产物，不重新构建。GUI 使用倍率 1、主端口 5555、实体端口 9400／9500；无界面使用倍率 20、主端口 5556、EntityPortOffset 10000，对应 19400／19500。启动前检查占用，禁止静默换端口或结束其他实例。原 WaterwaySearch 场景仍为 785 秒。

GUI 通过既有 ValidateRun 自动推进至少 20 秒后暂停并保留；无界面完整运行后退出。客户端连接等待上限 15 秒，连接后不重连；连续观察至少 10 秒，接收上限 30 秒，达到实体及会话状态要求后主动断开。入口恢复工作目录和控制台编码，并检查 36 项进程／用户／系统环境值及执行策略未改变。

既有 ValidateRun 将整个 GUI 运行视为一个源时间连续区间；暂停／继续适用，重置会使收尾的单调时间检查失败，即使应用正常退出。重置及场景切换的分段验收留给 G6；若人工操作触发重置，保留原诊断，以同版本受控复验取得正常收尾证据，不修改旧记录掩盖失败。

## 3. 封装、字段与原始证据

实际 Java 输出结构为：起始标记 `+=+=+=+=`、十进制正文长度、`#@#@#@#@`、地址／属性与 LMCP 正文、`!%!%!%!%`、外层字节和、`?^?^?^?^`。解析器按声明长度读取正文和尾部，不在二进制正文中搜索结束符。正文限制 1 MiB，属性限制 4 KiB，数字字段与待处理缓冲区均受限。

随后验证内部 `LMCP` 标记、声明长度、根对象有效标志、系列／类型／版本及完整校验和，再调用生成类的 unpack；检查实际消费长度和外层类型一致性。当前真实流量的内外层校验和均实际相符；没有使用生成工厂对零校验和的宽松接受行为。损坏帧明确失败，不通过静默重同步继续计为成功。

AirVehicleState 保留实体 ID、Time、经纬度、高度及 AltitudeType；SessionStatus 保留 ScenarioTime、StartTime、State 和倍率。ID 和 int64 时间字段在 JSON 中为字符串；仿真时间单位为毫秒，不解释为 UTC。经纬度单位为度，高度为米且保留原类型；不进行地形修正。实体源时间不倒退、位置实际变化、经纬高有效才算通过。

每个 `out/runs/g1-t05-receive-<时间戳>/` 包含 capture.bin、chunks.jsonl、frames.jsonl、decoded.jsonl、capture-result.json、result.json 和三个代表消息的 Sentinel／原始 LMCP 文件。原始字节保留每次 recv 的内容；完整帧索引、已验证字节范围与主动结束时的未消费尾部单独记录。远端 EOF 遇半帧为失败；主动结束截取的尾部不能冒充完整帧。
