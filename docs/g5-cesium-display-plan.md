# G5 实施方案：Cesium 态势显示与同源真实地形

修订日期：2026-09-20，Asia/Shanghai。本版依据用户后续决定及 T01～T04 实际证据更新原方案。**G5-T01～T04 已完成；T05 可执行，T06～T11 待前置。** T04 实施及验收已完成；后续按单卡范围推进。当前进度见 [状态](status.md)，执行范围见 [十一张任务卡](backlog.md#9-g5-顺序与任务卡)，后端接口见 [G4 → G5 交接](g4-g5-handoff.md)。

## 1. 目标、决定与现有资格

交付 Windows 原生运行的 Cesium 态势页面，消费 G4 真实消息，显示实体、姿态、轨迹、规划航线、执行状态、任务、区域和仿真时间；包含图层开关、属性查询、定位、跟随和视角复位。

当前采用 **原全球矢量底图＋USGS 区域主地形，Copernicus 只作对照**。AMASE 和 Cesium 从同一份标准化地形派生；经纬度统一为 WGS84，正高和椭球高分别定义、显式转换。原 Terrarium DEM 保留只读归档和异常回归，退出当前地形消费链。区域外采用明确标注未通过仿真资格的参考椭球浏览。

仿真控制与重置、历史回放、量测工具、地形避障算法和覆盖效果优化继续留待后续。第二机器部署和离线卫星影像包归 G8。全球底图浏览不等于全球地形或仿真合格；本轮仿真范围固定在西经 122～120 度、北纬 45～46 度，T04 三类小规模后端任务已通过，原两实体／20 实体显示联调仍须后续验收。

## 2. 技术方案与后续接口

### 2.1 前端与运行入口

现有 `apps/cesium_viewer/` 采用轻量 TypeScript 页面，无大型 UI 框架。沿用 T01 锁定的 Node 24.21.0／npm 11.19.0、TypeScript 7.0.2、Vite 8.3.0、Cesium 1.145.0。地理处理使用独立 Python 3.14.7、Rasterio 1.5.1／GDAL 3.12.4、PyProj 3.8.0／PROJ 9.8.1，保持与 G4 环境隔离；后续不因普通功能接入顺带升级工具或依赖。

页面目标仍为中文界面：中央三维场景、左侧实体与图层列表、右侧选中对象详情、底部后端时间及连接状态。T03 已有地图、图层／范围开关和地理定位；实体列表、详情、跟随和业务时间由 T05～T07 补齐，不能把当前“未连接”时间栏当作仿真时钟。

生产候选服务监听 `127.0.0.1:8080`，只读 HTTP／WebSocket 代理至 G4 的 `8000`；开发模式使用同一资源服务加 Vite 中间件，端口 `5173`。冲突明确失败，不静默换端口或结束其他进程。生产运行不依赖 Vite。已有构建／验收／启动命令见 [T03 标准入口](g5-map-validation.md#4-标准入口)，不将候选入口称作已发布正式前端。

Cesium Workers、ThirdParty、Assets、Widgets，以及固定 Noto CJK 字体和 OFL 许可已本地部署。模型资源完成 T06 资格后再纳入本地包。后续生产构建继续检查遗漏资源和错误 MIME／HTML 回退，保持断网可用。

### 2.2 地图资源服务与有界加载

PMTiles 通过 HTTP Range 按需读取，工作线程解码 MVT 并绘制为 Cesium 影像瓦片；全球底图要素与可查询业务对象分开。保留中文名称优先及原名回退。构建对主包计算完整摘要；日常启动检查大小、修改时间与头部，服务期间身份变化拒绝请求，不能把该启动检查写成全量重哈希。

| 现有接口／资源 | 后续必须保持的契约 |
| --- | --- |
| `/map/runtime.json`、`/map/health` | 地理版本、范围、高度语义及地图健康；地图就绪与后端 ready 分开 |
| `/map/planet.pmtiles` | HEAD 返回大小／ETag／Accept-Ranges；GET 单段最多 4 MiB，拒绝整包／多段／非法范围；416 和 If-Range 不符的 412 明确保留 |
| 矢量工作线程 | 压缩 Range 缓存 16 MiB／128 项，目录缓存 16 MiB／64 项；最多 4 个任务；解压最多 16 MiB，单次最多 20 万要素／100 万顶点／100 标签 |
| `/map/terrain/{z}/{x}/{y}.f32` | GeographicTilingScheme、z0～14、65×65、float32 小端、北到南／西到东；从 T02 椭球高度场直接作三角插值 |
| 地形与请求资源 | 服务保存一份约 11.5 MB 高度场，地形缓存最多 64 片／1,081,600 字节，前端地形请求最多 8 个；请求日志最近 128 条，HTTP 并发最多 64，WS 数量有上限 |
| `/api/v1/health`、`/api/v1/snapshot`、`/api/v1/stream` | 保留 G4 状态、消息和字符串整数；503／1013 不吞掉，浏览器只读消费，不增加控制接口 |

Cesium 未用瓦片缓存目标为 128，可见瓦片由视锥和细分层级另行管理；它不是所有可见 GPU 对象的硬数量限制。T10 须对地图、模型、业务缓存及浏览器进程／GPU 资源整体实测，不能只看上述缓存或一张 JS 堆快照。

默认本地矢量，Esri World Imagery 仅在用户切换时加载，保留服务元数据及当前视图来源标注。初始化超时或瓦片失败时提示并恢复本地底图；本机断网浏览与实际在线加载已由 T03 验证。在线故障不影响真实后端的要求仍须在 T05／T08 的真实链路验证，T03 的协议夹具不能代替。在线缓存不算离线卫星影像包。

区域外只提供明确未验收的参考椭球浏览；区域切边不延拓，不拼接旧 DEM 或 Copernicus，不把截断边缘算作全球地形接缝合格。区域内缺失／坏数据必须拒绝，不能落到零高程后继续宣称合格。Web Mercator 极区数据边界同样不取得地形资格。

### 2.3 同源地形、WGS84 与高度转换

“统一为 WGS84”指明确经纬度参考系，同时管理高度基准；不要求两端高度数值相同，也不能只改 CRS 名称。当前共同依据是标准化正高网格，禁止 AMASE 直接使用 USGS 原值而 Cesium 独立使用 Copernicus。

| 环节 | 固定定义及派生规则 |
| --- | --- |
| USGS 主源 | NAD83／NAVD88，`EPSG:4269+5703`；原生像素中心双线性采样，重叠区固定西侧优先，无平均或缺值回退 |
| 标准化 `orthometric.tif` | WGS84 经纬度／EGM96 正高，`EPSG:4326+5773`；3 角秒，2401×1201，float32，共 2,883,601 个有效节点 |
| AMASE DTED Level 1 | 从同一正高网格派生两幅 1201×1201，整数米、五取偶量化；量化误差最多 0.5 米，共边 1201 个节点一致 |
| Cesium `cesium-heightfield.f32` | WGS84 椭球高，`EPSG:4979`；从共同网格按 `h=H96+N96` 转换一次；T03 瓦片不再叠加地面高程或改正 |
| Copernicus 对照 | WGS84／EGM2008，经 `H96=H2008+N2008−N96` 统一后单独比较；它是 DSM，与 USGS 裸地高程语义不同，不作主源填补或替代 |

转换采用已冻结的 NAD83→HARN（EPSG:8556、NADCON5）→NAVD88 正高到 HARN 椭球高（EPSG:9160 逆、GEOID99）→WGS84（EPSG:1901），再减 EGM96 得共同正高。完整定义见 [USGS 坐标操作](../config/g5-usgs-operation.json)。四份 NADCON5／GEOID99／EGM96／EGM2008 网格按摘要消费，PROJ 网络关闭；不把 NAD83 重标为 NAD83(2011) 以套用 GEOID18。更换转换模型或扩大范围须新建输入版本并复验。

所选操作保留较早 GEOID99 和 WGS84 框架近似限制：登记模型精度 1.1 米，加 EGM96 后 2.1 米，是模型不确定性；独立数值计算误差不超过 1 米是实现判据，两者不混同，也不宣称 DEM 绝对测绘精度。NADCON5 分片切换的厘米级残差已取证，保持固定 0.05 米水平残差上限及超限拒绝，不宣称任意节点逐位可逆。

当前 USGS 1/3 角秒源在区域中部约为南北 10.29 米／东西 7.24 米；共同 3 角秒网格约为南北 92.62 米／东西 65.13 米。T03 的 65×65 显示网格、DTED 整米量化和 20 米覆盖统计栅格另行记录；更密显示采样不会提高源地形精度。原 Terrarium z10 约 107 米仅属历史源间距，不能继续标作当前主源分辨率。

AMASE 保留正高计算，Cesium 显示使用椭球高。T04／T06／T07 必须逐类登记实体、航点、任务几何和区域高度的源字段语义：相对地面高度先按实际语义处理，正高再作一次椭球高转换；已是椭球高的地形不得重复改正。保留原消息值及转换配置版本。区分 AMASE 最近邻、双线性、DTED 量化以及 Cesium 三角插值，同源不要求不同插值结果在任意位置逐位相同。

### 2.4 消息、时间与状态

- 保持 [G4 浏览器协议 v1](g4-browser-contract.md)，新增 TypeScript 类型、归约器和运行绑定配置，不增加仿真控制接口。同一 WS 先收到快照，再严格连续应用增量；不能拼接独立 HTTP 快照与另一个 WS 的增量。
- ID、时间和序号保留十进制字符串，比较使用 `BigInt`；upsert 替换完整对象，delete 显式删除。新运行、新流、缺口或重连时清除旧业务缓存与插值样本，等待新快照；恢复期间显示过期／恢复中，不能虚报 live。
- 后端时间是唯一权威，不解释为 UTC。允许约 1 秒插值缓冲，显示不得超出已收到的样本；暂停、断流和结束停止推进。浏览器墙钟、相机、底图切换不改变仿真。
- 实际轨迹保留最近 10 分钟，每实体最多 2048 个样本；刷新后从新快照重新积累。完整规划航线独立保存，不随分段命令缩短，也不宣称补回旧轨迹。
- 命令收到、观察到执行和后端报告完成分别呈现。TaskComplete 不删除任务或实体，不停止实体终端飞行；删除、过期、完成各按协议处理，不能凭预测或视觉位置冒充执行证据。
- T05 使用当前合格真实后端／网关完成首次接入、晚加入和刷新；T08 再验证观察链路／网关恢复与浏览器故障隔离。T03 夹具覆盖的超大整数、503／1013 作为回归保留，不升格为真实联调结果。

### 2.5 用户模型接入

T06 先选择适合当前仿真实体的 OSGB 样本验证读取和转换，再形成 glTF 2.0／GLB 候选；冻结转换工具版本、原件与产物摘要。不能修改后缀代替转换，也不能根据文件名就认定模型类型、LOD 或材质完整。

检查几何、纹理、透明度、外部资源和可能的动画，验证本地离线加载；未发现独立纹理文件不等于纹理缺失。登记来源／授权、长度单位、尺寸、前向／上向轴和原点，把资产固定修正与后端航向／俯仰／滚转分开，完成四向及姿态校准后建立实体到资产的显式映射。显示资产不改变后端实体类型或增加仿真能力。

16 个原件是可选显示资产库，不新增 16 类场景或全模型仿真验收要求；实际选用资产取得显示资格，未接入项保留登记。UH-60 约 71.7 MB、AH-64D 约 55.0 MB，若选用须在 T06 记录转换后的几何／纹理、加载和内存开销，T10 纳入实际模型组合测试；high／lo／icon 的远近策略由实际内容决定。T11 打包全部选用资产、外部资源和必要许可。

### 3.1 T04 地形场景与后端检查

已完成，见 [后端地形报告](g5-backend-terrain-validation.md)。三份副本共 914 个任务点按共同正高赋值；包络及外围 5 公里最大量化地形 990 米，统一抬升 390 米，配置至少 100 米净空；两模式实际采样最低净空均为 340 米。后续场景、转换或来源变更须重新冻结并验收。

地形场景使用独立身份，保留 G4 零高程基线。地面任务按共同标准化地形赋高；初始经纬度和任务平面几何保持，原例完整 90 点水道、20 实体固定对应及矩形尺寸不得缩减。

取证前按固定规则生成必要飞行高度适配：检查场景飞行范围及外围 5 公里内的最高地面高程，统一抬升相关飞行高度，至少保留 100 米仿真净空；记录原值、新值、基准、抬升量和地形版本，冻结差异。最高值以本轮标准化地形为依据，核查 DTED 量化对最终净空的影响；允许必要高度适配，不据此优化覆盖效果。T02 的输入几何包络通过不能替代实际规划／飞行检查。

T04 按下列次序完成，后续修改或扩大范围仍沿用此资格流程：

1. 复查 T02 候选／验收双编号、实际文件、转换资源和当前后端来源，核查全部任务几何、预定飞行范围及 5 公里外围。查询边界沿用配置的西／南含、东／北不含，保留的外缘网格节点只用于插值；越界或数据缺失明确失败。
2. **先审计 AMASE 已知 DTED 问题的实际影响**：负值符号幅度编码被误读，−100 米曾读成 −32668 米；dlat／dlon 元数据存在十倍间距错误。当前区域 DTED 为非负 2～3419 米，最近邻／双线性按节点数定位已通过，不能据此认定飞行、传感器和分析的所有调用都安全。
3. 追踪实际使用路径并验证坐标、间距、边界和非零地形查询。负高程在修复前继续拒绝；若已知问题影响本轮计算，按既有来源规则修改源码、重建及复验，取得合格后端后再执行。若某缺陷不影响本轮路径，保留调用证据和区域限制，不宣称已修复或推广为全球资格。
4. 在独立场景中完成点／线／区域小规模真实规划、执行及完成，证明地形实际参与飞行、传感器和分析；按本次采样窗口独立复算线／区域 20 米覆盖计数及点观察时间，正常退出并释放端口。

规划或实际飞行越出合格区域、净空不满足冻结规则、统计不一致或退出失败均判失败。不得删除 G4 零高程检查条件就宣称真实地形通过，也不得通过裁剪水道或调参追求覆盖率解决功能失败。必要后端修改会使受影响的来源绑定需要更新和复验，保留旧记录，不能修改旧 manifest 绕过。

## 4. 验收标准

| 类别 | 必验条件 |
| --- | --- |
| 坐标与姿态 | 独立数值转换误差 ≤1 米、姿态误差 ≤0.1°；高度正负、经纬度顺序、模型轴和跨瓦片边界均校核。明确其不是源 DEM 或转换模型的绝对测绘精度 |
| 地形与统计 | 同源节点、AMASE 实际查询、Cesium 高度场及转换链可对照；量化和插值差异分别解释。20 米覆盖栅格、线／区域计数、点观察时间独立复算，不设最低覆盖率或观察时长 |
| 状态与恢复 | 超大 ID、快照后增量、重复／乱序／缺口、删除、跨运行隔离、503／1013、新流恢复及后端退出；完成状态一致，后端失效不续接旧运行 |
| 真实显示 | 原两实体和混合 20 实体都有真实规划／执行／完成证据，源消息、规范化对象和 Cesium 属性可关联；固定样本和页面截图不能代替 |
| 稳定性 | 正确性、可操作、缓存和资源有界为硬条件；约 30 FPS 为目标，无 FPS 或 250 ms 硬门槛；记录帧率、延迟、内存、CPU／GPU、恢复时长及模型资源 |
| 运行与发布 | 生产资源完整，断网本地矢量、区域地形、字体及选用模型可用；不同目录、中文空格路径、端口冲突、资源损坏、重复启停及所属进程正常退出通过；本轮人工确认绑定页面、运行和候选包 |

T10 的两种后端模式顺序运行，各真实 1 倍推进 1800 仿真秒；三客户端覆盖正常查看、刷新／晚加入及慢消费，恢复后收敛到同一运行的完整状态。逐架验收执行／完成，保留任务完成后的真实终端飞行。沿用每模式 2700 墙钟秒自动运行预算，人工确认等待独立计时。

性能记录包含实际机器、浏览器版本和实际渲染器、窗口分辨率、视角、图层／模型组合、真实源更新率、采样窗口及方法；不能仅凭显卡型号推断硬件加速。区分 JS 堆、浏览器／服务进程内存与 GPU 指标。T03 实测 ANGLE／NVIDIA／D3D11 仅证明该轮渲染器，不代替 T10 的长期性能和泄漏检查。

坐标／姿态固定样本保留为独立校准；真实场景未自然触发的区域或删除边界须明确标为独立协议／渲染测试，不能冒充现场事件。地图断网、影像故障回退、浏览器销毁和资源上限回归按后续修改影响执行。
