## 1. 目标与边界

交付 Windows 原生运行的 Cesium 态势页面，消费 G4 真实消息，显示实体、姿态、轨迹、规划航线、执行状态、任务、区域和仿真时间。

- 使用用户现有全球矢量底图，验收区域改用 USGS 主地形、Copernicus 对照，增加可切换的 Esri 在线卫星影像。区域外旧 DEM 的浏览资格单独处理，不因区域替换而宣布全球地形合格。
- Cesium 与 AMASE 使用同源高程，重新验证真实地形下的任务执行和统计。
- 包含图层开关、属性查询、定位、跟随和视角复位。
- 仿真控制、重置、历史回放、量测工具、地形避障算法和覆盖效果优化继续留待后续。
- 全球数据用于浏览；仿真资格限定在本轮验收区域。第二机器部署和离线卫星影像包仍归 G8。

## 2. 技术方案与接口

### 2.1 前端与运行入口

- 新建 `apps/cesium_viewer/`，采用 TypeScript、Vite、CesiumJS，首版使用轻量页面组件，不增加大型 UI 框架。
- Node.js 采用 24 LTS 系列；T01 固定具体版本、依赖锁及下载摘要。工具仅在项目进程内启用，地理处理工具使用独立 Windows 环境，不能污染 G4 的已锁定 Python 环境。[Node 发布计划](https://github.com/nodejs/Release)
- 页面采用中文界面：中央三维场景、左侧实体与图层列表、右侧选中对象详情、底部后端时间及连接状态。
- 正式页面服务默认监听 `127.0.0.1:8080`，代理 G4 的 HTTP／WebSocket 接口至 `8000`；开发服务使用 `5173`。端口冲突明确失败，不静默更换或结束占用者。
- Cesium Workers、ThirdParty、Assets、Widgets、模型及字体本地部署，生产运行不依赖 Vite 开发服务器。[Cesium 资源部署要求](https://cesium.com/learn/cesiumjs-learn/cesiumjs-quickstart/)

上述前端、服务、配置和工具均为规划。正式脚本名称及可复用命令在对应任务落地并验证后登记；不提前写成已验证运行入口。

### 2.2 地理资源

- 保留用户目录布局，配置分别指向 `tiles/tiles/planet.pmtiles` 和 `tiles/dem/`。原始数据只读，派生产物放入 `out/`；T01 将数据目录及压缩包加入忽略规则，数据本体不入 Git。
- PMTiles 通过支持 HTTP Range 的本机资源服务按需读取；浏览器使用有界缓存和工作线程解码 MVT，将底图要素绘制为 Cesium 影像瓦片。实体和任务保持独立、可查询的业务图层，不把全球矢量包整体加载进内存。[PMTiles 读取机制](https://docs.protomaps.com/pmtiles/)
- 默认显示本地矢量底图；Esri World Imagery 按用户切换加载。在线服务失败时提示并恢复本地底图，仿真继续运行；保留服务来源标注，配置中记录服务地址和访问条件。G5 不将在线浏览缓存算作离线影像包。
- 原 DEM 的 Terrarium 解码、XYZ 行列、像素中心和异常证据保留。验收区使用固定 USGS GeoTIFF，经源坐标／高程转换后派生；Copernicus 的 DSM 与 EGM2008 基准单独处理。不同来源不静默混合或用于缺值回退；全球分级浏览及区域边界衔接由 T03 另验。[Terrarium 格式](https://github.com/tilezen/joerd/blob/master/docs/formats.md)
- 不把约 107 米的源像素间距、重采样后的网格间距或 20 米覆盖统计栅格混写为地形精度。两极超出 Web Mercator 数据范围的部分明确标注数据边界，不宣称已有极区地形资格。

### 2.3 同源地形与高度

- 先核查验收区域的实际高程来源和垂直基准，再建立转换清单。不能仅凭 Terrarium 编码推断全世界采用同一高程基准；上游数据包含多个来源。[上游来源说明](https://github.com/tilezen/joerd/blob/master/docs/data-sources.md)
- 验收区域生成固定的标准化高程栅格，同时派生 AMASE DTED Level 1 和 Cesium 高度场；记录重采样方法、垂直转换、改正网格和文件摘要。
- 经纬度统一为 WGS84。USGS 输入为 NAD83／NAVD88，标准化网格为 WGS84／EGM96 正高，Cesium 为 WGS84 椭球高；不能仅把 CRS 名称改为 WGS84，或假定 WGS84 经纬度要求所有高度数值相同。标准化正高是两端共同输入，DTED 米级量化与 Cesium 高度转换分别留证。
- AMASE 保留正高计算；Cesium 使用相应椭球高。实体、航点、任务几何和地形共享转换配置，禁止重复叠加地面高程或大地水准面改正；原始消息高度及基准保留用于对照。
- 区分 AMASE 最近邻取样、双线性查询与 Cesium 网格插值，分别验证；“同源”不等于任意位置的不同插值结果逐位相同。
- 来源、基准、覆盖范围或转换资源未核实时，停止地形资格验收；不得静默使用零高程通过。修复源代码或配置输入时按既有来源规则重建／复验，不改写历史哈希。

### 2.4 消息、时间与状态

- 保持 [G4 浏览器协议 v1](g4-browser-contract.md)，新增前端 TypeScript 类型、运行配置和地理资源清单，不增加仿真控制接口。运行配置将本次后端身份、前端版本和地理资源版本关联起来。
- 同一 WS 连接先接收快照，再严格连续应用增量；不能将独立 HTTP 快照与另一个 WS 的增量拼接。ID、时间和序号保留字符串，比较使用 `BigInt`。
- 新运行、新流、序号缺口或重连时清除旧业务缓存和插值样本；恢复期间明确显示过期或恢复中。连接只读，不回送任务、命令或收到的业务消息。
- 后端时间为唯一权威，不将仿真毫秒解释为 UTC。显示可使用约 1 秒的插值缓冲，但不得超出已接收样本；暂停、断流和结束立即停止推进。
- 实际轨迹默认保留最近 10 分钟，每实体最多 2048 个样本；刷新后从新快照重新积累，不宣称恢复了历史轨迹。完整规划航线独立保存，不随分段命令缩短。
- 命令收到、观察到执行、后端报告任务完成分别呈现；任务完成不删除实体或停止其终端飞行。对象删除、过期和完成采用各自语义，未知执行航段不能根据规划或视觉位置冒充已执行。

### 3.1 地形场景适配规则

地形场景使用独立身份，保留 G4 零高程基线。地面任务位置按 DEM 赋高；初始平面位置和任务平面几何保持，原例完整 90 点水道、20 实体固定对应关系及矩形尺寸不因地形接入缩减。

必要的飞行高度适配在取证前按固定规则生成：以场景飞行范围及外围 5 公里内最高地面高程检查净空，统一抬升相关飞行高度至至少保留 100 米仿真净空，并冻结差异清单。这里的“初始位置保持”指经纬度保持，高度允许上述必要适配。该规则用于功能适配，不据此开展覆盖率寻优；实际规划或飞行越出合格区域时判失败。

T04 必须先验证真实地形下的小规模规划、飞行及统计，不能把 G4 的零高程统计反例删除后直接宣称通过。后续 T09／T10 分别建立真实地形完整任务及规模证据；统计结果允许与零高程历史结果不同，但须和本次独立复算一致。

## 4. 验收标准

| 类别 | 必验条件 |
| --- | --- |
| 坐标与姿态 | 独立基准验证数值转换误差不超过 1 米、姿态误差不超过 0.1°；这些指标不代表原 DEM 的绝对测绘精度。校验高度正负、经纬度顺序、模型轴和跨瓦片边界。 |
| 地形与统计 | 同源节点、AMASE 查询、Cesium 高度场及转换链可对照；覆盖栅格保持 20 米。线／区域覆盖计数和点观察时间独立复算，不设置最低覆盖率或观察时长。 |
| 状态与恢复 | 覆盖超大 ID、快照后增量、重复／乱序／缺口、删除、跨运行隔离、503／1013、新流恢复及后端退出。完成状态与后端一致；后端失效不续接旧任务。 |
| 真实显示 | 原两实体和混合 20 实体均有真实规划、执行及完成证据；固定样本和页面截图不能替代真实联调。 |
| 稳定性 | 正确性、界面可操作、缓存及资源有界为硬条件；约 30 FPS 为目标，记录帧率、延迟、内存、CPU／GPU 和恢复时长，不设置 FPS 或 250 ms 硬门槛。 |
| 运行与发布 | 生产包资源完整，断网本地矢量和地形可用；不同工作目录、中文空格路径、端口冲突、资源损坏、重复启停及所属进程正常退出通过。人工确认绑定本轮页面、运行和候选包。 |

性能记录必须包含实际机器、浏览器版本与渲染器、窗口分辨率、视角、图层组合、真实源更新率和测量方法；不能仅凭显卡型号推断硬件加速有效。20 实体两模式顺序运行，各实际 1 倍推进 1800 仿真秒；三客户端覆盖正常查看、刷新／晚加入和慢消费，恢复后收敛到相同快照状态。保留任务完成后的真实终端飞行与状态更新。沿用每模式 2700 墙钟秒的自动运行预算，人工确认等待独立计时。

坐标／姿态已知样本用于独立校准；完整联调还须把真实源消息、规范化对象和 Cesium 属性逐项关联。区域和删除边界若固定真实场景未自然触发，须保留明确标为独立协议／渲染测试的证据，不能冒充现场事件。
