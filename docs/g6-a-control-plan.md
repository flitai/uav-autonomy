# G6-A 基础仿真控制实施卡

日期：2026-09-24。G5-T11 已发布；本页是 G6-A 的实施契约，运行资格以各卡的真实收据为准。

当前进度：A01～A05 已按修复后的源码完成独立自动复验、用户视觉确认、同源码正常退出和本地正式发布；生产入口 GUI 复验通过。用户实测会话第二段的断流失败原始记录保留，正式正常退出采用独立 GUI 复验，见 [G6-A 验收记录](g6-a-control-validation.md)。G6-B01 为下一卡。

## 1. 控制边界

G6-A 提供开始／继续、暂停、0.25／0.5／1／2／5／10 倍速、整组重置，以及只读仿真时间与进度。页面只对本机当前受控会话写入；G4 快照与 WebSocket 继续只读。总时长读取本次冻结场景的 `ScenarioDuration`，当前已验收小场景为 1800 秒；缺少有效总时长时仅显示后端时间，不计算百分比。进度不可拖动，历史回放归 G7。

AMASE `SimControls` 直接调用 `SimTimer.go/pause/setRealtimeMultiple`；`SimTimer` 发布的 CMASI `SessionStatus` 是状态反馈，不是网络控制命令。`ScenarioManager` 收到 Reset 会重新装载场景，但 UxAS 的规划、命令和网关状态并不因此自动获得新运行身份。因此 G6 运行配置已移除旧 `SimControls` 控件，页面通过运行目录内的受限命令通道控制；重置由编排器关闭整组并以新分段启动，禁止只向活动 AMASE 注入一个 Reset 状态消息。

## 2. 运行与接口契约

每个受控会话有 `runId`、从 1 开始的 `segmentId`、后端 `run_id` 与网关 `stream_id`。新分段重新启动 AMASE、UxAS、网关及分析收集器；旧分段的请求、确认和快照均不能用于新分段。服务端串行处理控制操作，并持久保存操作 ID、幂等键、预期身份、动作、目标倍率、提交时刻、AMASE 本地受理和权威 `SessionStatus` 反馈。未知反馈保持 `uncertain`，阻止冲突操作；不能把 HTTP 受理或文件写入写成控制成功。

| 动作 | 允许状态 | 成功反馈 |
| --- | --- | --- |
| 开始／继续 | 本段初始化完成且暂停；运行中重复请求只返回原状态 | 同段 `SessionStatus.Running` 且仿真时间随后推进 |
| 暂停 | 运行中；已暂停重复请求只返回原状态 | 同段 `SessionStatus.Paused`，后续时间保持稳定 |
| 倍率 | 本段已就绪，值来自固定集合 | 同段 `SessionStatus.RealTimeMultiple` 与请求值一致；运行中的时间仍连续 |
| 重置 | 本段已就绪且无结果待核实操作 | 本组正常关闭、新 `segmentId` 与新后端身份、场景时间回起点、旧流和旧操作被拒绝 |

当前接口为 `GET /api/control/v1/state`、`GET/POST /api/control/v1/operations` 和 `GET /api/control/v1/operations/{key}`。写入只接受本机 8080 页面来源、最多 1024 字节 JSON 白名单字段、预期 `runId/segmentId/controlSequence` 和幂等键；服务端一次处理一条写请求，前一结果待核实时拒绝冲突操作。操作 ID 由服务端生成，查询返回 `pending/applied/confirmed/rejected/uncertain` 之一。倍率和时间始终以 AMASE 报告为准；原始仿真毫秒用字符串，浏览器用 `BigInt`。单独的全局频率额度尚未实现，不作为本轮已验证能力登记。

Java 运行内探针 `scripts/g6_control/ControlProbe.java` 只执行受限暂停／继续／倍率，读取运行目录中单个编号请求并原子写入处理结果。探针没有网络监听或重置入口；编排器负责写入请求、确认反馈和整组重置。它是候选源文件，编译成功不代表真实运行已通过。
