# G5-T06 补充：近景跟随顿挫与前后抖动

日期：2026-09-21，Asia/Shanghai。本轮解决用户反馈“放大后还是顿挫，而且不时会前后抖”。保留银灰金属机体、阵营细描边、固定屏幕尺寸和后端时间语义；当前可启动候选以本报告为准，下一实施卡仍为 G5-T07。

## 定位与修复

旧版本的世界坐标已逐帧插值，但镜头仍会停住再追赶。使用真实 G4 数据、独立 Edge 页面和 postRender 采样确认：384 px 模型、约 43 米相机距离，屏幕锚点最大单帧跳动 **108.13 px**，实际尺寸相对最终相机的计算偏差最高 **9.41%**。原始 5 秒／160 帧记录位于 out/runs/g5-close-motion-before-20260921-1440/。

关闭轨迹的对照位于 out/runs/g5-close-motion-isolate-20260921-1445/：开轨迹近景跳动 79.82 px；关闭轨迹后锚点跳动低于 0.000001 px，但尺寸仍有最高 1.24% 的帧偏差。两次观察浏览器均正常退出。观察使用同一后端场景、不同飞行时段，不把这些值当成同一段飞行的性能基准。

锁定 Cesium 1.145.0 源码确认两处时序问题：

1. 原轨迹更新替换 ConstantProperty，触发异步静态折线重建。DataSourceDisplay 就绪／包围球可能 pending；CesiumWidget._onTick 只有包围球 DONE 时才更新跟随 EntityView，因此镜头连续几帧不动，之后突然追上实体。
2. ModelVisualizer 先于原生跟随镜头计算 scale，使用上一帧相机与当前实体位置；镜头追赶时尺寸也随之变化。

[实体层](../apps/cesium_entities/layer.ts) 现在在同一 CustomDataSource.update 中先插值，再同步跟随相机 ENU 原点，随后可视化器计算模型、标签和尺寸。使用公开 camera.lookAtTransform，保留用户相机局部位置、方向、上向和右向，不等待几何包围球。跟随参考系显式为 ENU，保留原生选择／跟随管理，不改引擎私有字段。定位／复位／重跟随清理相机目标，防止快速切换时把世界坐标偏移当成局部偏移。

轨迹改用 CallbackProperty 返回有界位置缓存，让 Cesium 更新动态折线，避免反复提交静态几何重建。10 分钟／2048 源样本上限、轨迹和详情限频、删除及恢复清理保持。模型资产、姿态计算、播放游标、后端、G4、T02～T05 和地形数据保持。
