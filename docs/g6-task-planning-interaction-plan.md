## 1. 项目定位与阶段安排

项目定位为**具有侦察监视任务库的通用自主任务规划框架**。复用 UxAS 的任务服务、任务分配、顺序安排、路线计算和计划管理能力，以 AMASE 验证执行及统计，在本项目中补齐 Cesium 任务操作界面和后端业务接口。通用性体现在统一任务契约、规划流程与扩展方式；任务库优先服务搜索、侦察和持续监视。

保留总体 G0～G8 编号，将尚未实施的 G6 分为两个按顺序推进、独立验收的部分：

## 2. 功能范围与复用边界

### 2.1 首批交互任务

首批使用已经验证的 CMASI `PointSearchTask`、`LineSearchTask`、矩形 `AreaSearchTask`，为新的交互调用方式另建资格。

- 地图上创建点、折线和矩形，配合数值表单修改位置、尺寸和任务参数；支持选中、撤销未提交编辑、保存草稿、复制草稿和删除草稿。
- 按任务选择固定执行实体或候选实体集合；展示所需传感器、资格限制、已占用状态和不能参与的原因。候选来自后端真实配置与状态，显示阵营或模型大小不能当作性能条件。
- 使用经过验证的运行区域与约束模板，编辑允许开放的任务字段。经纬度顺序、单位、地形覆盖及高度基准明确；不把任意地图位置都当作合格仿真区域。
- 显示规划分配、任务顺序、各机完整航线和规划器可提供的预计代价；区分待审查方案、已下发计划和实际轨迹。预计代价不是实飞覆盖率。
- 确认具体方案后下发；显示操作结果、实际执行证据、完成状态和统计。刷新页面可以恢复这些业务状态。

B01 冻结可编辑字段、范围和默认值。现有覆盖统计只资格化零 `DwellTime` 的点／线／矩形组合；首批模板保留此限制，非零值须另验后开放。其他参数、任务关系或区域约束超出已验证组合时，必须增加对应真实验收，不能由输入框存在推断可用。

首批编辑器面向任务意图，继续保留 AMASE SetupTool 管理实体性能、传感器配置和完整场景。任意形状区域、任意任务关系表达式及完整 Web 场景编辑器不作为本轮最小交付。

## 3. 用户操作流程

1. **选择本次运行与实体**：查看后端就绪状态、权威时间、合格区域及可用飞机。只读观察可继续使用；状态过期或后端未就绪时不能发起业务操作。
2. **建立任务草稿**：选择类型、绘制几何、填写参数，指定候选实体及允许的任务顺序／区域约束。草稿尚未改变正在执行的任务。
3. **校验并请求规划**：后端验证草稿版本、实体与地理资格，准备上下文，等待任务初始化，再向 UxAS 发请求；界面显示处理中、失败原因或无可行方案。
4. **审查结果**：查看分配、任务次序、完整航线、输入状态时刻和约束检查。修改输入形成新版本并重新规划，旧结果保留为历史或标为失效，不覆盖正在执行的计划。
5. **确认下发**：用户明确选择方案版本。后端再次检查运行身份、输入修订、实体可用性及方案时效，确认一致后才允许执行；过期则要求重新规划。
6. **跟踪执行**：分别显示请求已受理、计划已生成、命令已发送／收到、观察到执行及后端报告完成。没有相应证据时保持待确认，不以成功 HTTP 响应或计划航线替代执行。
7. **按需重新规划**：从最新状态建立替代方案，展示受影响实体／任务及新旧差异；经确认后受控切换。未提交草稿可随时删除，放弃候选方案不影响当前任务。

完成任务仍保留实体及其终端飞行。删除草稿、取消待处理规划、废弃候选方案、替换活动任务和终止实体行为是不同操作；初版不以删除页面对象或发送任务删除消息冒充停飞。若需要终止活动任务，必须先定义可验证的后续盘旋等行为，再另行开放该操作。

### 4.1 规划预览必须无执行副作用

当前 `WaypointPlanManagerService` 会把 `AutomationResponse` 转为执行命令，任务服务也可能产生传感器动作。新增交互不能直接复用当前演示入口的“规划后立即执行”配置作为预览。

B02 优先验证隔离的预览规划实例，由受控业务服务提供冻结上下文，预览实例无通向活动 AMASE 的命令出口；也可采用经证明等效的执行门控方案。须覆盖航点／车辆动作、云台／传感器动作和任何旁路，默认未确认就拒绝进入活动执行链。最终拓扑、端口和生命周期在该卡冻结。

确认后只激活用户审查过的任务定义和同一份计划，不能偷偷再次计算并执行另一份结果。预览候选过期或不能安全映射到执行实例时，重新生成候选并再次审查。保留原自动演示运行模式作为独立入口，不让其自动请求服务与交互模式同时竞争同一实体。

### 4.2 版本、幂等和恢复

- 运行身份／重置分段、任务草稿修订、规划请求、方案、操作及命令均有明确关联。LMCP int64 标识和时间继续用字符串；前端比较沿用 `BigInt`，不要转成不安全的 JavaScript 数值。
- 方案绑定任务几何、参数、候选实体及其配置／状态时刻、运行区域、地形／高度配置、规划器配置和来源摘要。B01 定义有效性检查和预算，B04 验证运动中状态变旧的拒绝；不能以“仍是同一个 runId”作为唯一有效性条件。
- 写入采用版本冲突检查，同一实体同一时段的活动计划由后端统一管理。两客户端竞争应得到明确冲突，不能由最后一个网络包静默覆盖。
- 重复请求返回同一操作结果；超时／断线后先查结果，不因确认响应丢失而重发执行命令。不能确认是否已下发时标为结果待核实，并阻止冲突操作。
- 规划迟到响应、旧分段结果、已废弃候选不得被下发。重置使旧候选失效；网关恢复须恢复操作记录与后端状态关联，状态不完整时只读观察。
- G4 浏览器 v1 和只读覆盖接口保持已有消费契约；新增版本化业务写接口与操作事件，不把任意 LMCP／XML 透传给浏览器。是否新增观察投影及其兼容方式由 B01 冻结。
- 延续本机监听、显式端口和所属进程管理；写入口限制允许的页面来源与会话，校验负载、任务数量和队列上限。部署权限模型按单机范围实现，远程多用户部署另行设计。
