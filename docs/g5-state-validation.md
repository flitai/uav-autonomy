## 2. 协议、缓存与时间

每个 WS 连接先接收一次完整快照，再严格连续应用 delta；upsert 替换完整对象，delete 删除对应键，simulation 单独替换。一个包全部检查后提交；非法包、未知版本、重复快照、重复／乱序／缺口、身份变化、错误类型和超限输入清空业务状态并要求新快照。ID、源时间和序号保留原十进制字符串，比较用 BigInt；嵌套 LMCP 值和高度基准保持，不转 UTC、不在本卡叠加地形或大地水准面改正。

生产页面仅 GET health 和被动接收 WS，不请求 HTTP snapshot 拼接增量，不发送 WS 业务包。health 的 ready、运行／流身份和 freshness 与同连接快照一致后才显示“已同步”；HTTP 200 本身不表示就绪。503、1013、连接丢失、流失配和消息过期触发清理及有上限的重试。断开后仅显示标为过期的最后时间，业务对象和轨迹清空；新运行和新连接不沿用旧样本。

缓存固定于 [g5-state.json](../config/g5-state.json)：单包 8 MiB，各集合最多 4096 个对象，全部业务 JSON 字节预算 32 MiB；保留完整当前规划，不随分段命令缩短。轨迹最多 128 个实体，每实体最多 2048 点、最近 10 分钟，仅积累新连接的增量，按后端仿真时间淘汰，包括停止更新的实体。轨迹只保留时间、位置与姿态的固定字段；这不是完整历史，也不是 JavaScript 堆的 32 MiB 上限。

时间直接显示后端 simulation_time_ms，不按墙钟外推；暂停和断流不推进。命令 received、execution_observed 与任务 backend_completed 原样分离，任务完成不删除实体或完整规划。本卡没有增加仿真控制按钮，运行入口的暂停／正常收尾属于运维编排。
