- **目标**：建立能实际运行的 JDK 11 兼容基线和 Ant，先落实生成物管理，再允许首次构建。
- **前置条件**：G0 已通过；重查用户工作区及工具状态。若已有合适工具优先验证，避免重复安装。
- **修改范围**：必要的 Windows 环境／启动辅助脚本、根级精确忽略规则、阶段记录；按本任务需要准备 JDK 与 Ant。
- **范围边界**：不准备 C++／Node，不升级业务依赖，不生成消息代码或构建 AMASE。
- **实施步骤**：选择并固定具体 JDK 发行版／补丁版本、Ant 版本及来源；记录下载校验值、许可入口和实际安装路径；尽量由项目脚本管理进程环境；确定 Ant build／dist 的输出策略；加入 out 与必要中间产物的精确忽略规则。
- **验收条件**：同一 PowerShell 环境下 java、javac、ant 版本命令成功，退出码为 0；java 与 javac 来自同一 JDK；记录 Java 8 源码与 Java 11 工程的后续兼容验证安排；git check-ignore 显示计划生成路径被正确忽略，随库 JAR 仍受跟踪。
- **证据**：实际路径、版本输出、命令与退出码、来源及校验记录、忽略规则检查。具体版本在本任务固定，G0 不预填“已验证”值。
- **回退方式**：恢复本任务更改的环境与脚本；仅处理本任务新增且确认归属的工具／输出位置，保留原环境和随库文件。
- **停止条件**：JDK／Ant 来源不可确认、版本命令无法运行，或必须改变 Java 源码标准才能继续；记录有限排查结果后重新评估，不同时迁移整个构建体系。
- **关联风险**：R02、R07。
