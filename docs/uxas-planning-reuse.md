# UxAS 规划能力复用清单

核对日期：2026-09-23。依据为本仓库上游源码、示例、当前 Windows 构建清单和已经完成的项目验收。本文说明可复用能力与接入边界，不新增实施任务或运行资格。

**当前可复用的核心是整条任务级规划与执行链：请求校验 → 任务选项 → 路线与代价 → 分配与顺序 → 完整计划 → 分段命令。** 点、线和矩形搜索已经通过本项目真实规划、执行及统计验证；上游还包含多种后续可接入的任务。

“已有源码”“已纳入 Windows 构建”“当前场景启用”“已完成真实运行验收”分别代表不同程度。一个任务服务被编入 `uxas.exe`，不表示 Cesium 已提供该任务的输入、显示、控制和统计。

UxAS 的定位是**以规划算法为核心的自主任务后端软件**。它包含算法，也包含任务服务、消息通信、状态管理、请求校验、计划组装和执行命令管理，因此超出了单纯算法库的范围。如果“规划工具”指供人画任务、编辑约束、比较方案和确认下发的完整图形应用，当前 UxAS 自身不提供这套前端；如果泛指用于规划的软件，UxAS 也可以称为规划工具。两种说法的差异在于“工具”的使用范围，不能由没有图形界面推断它只有算法。

在本项目中，可分别理解为：规划算法负责计算，UxAS 后端组织并执行规划流程，AMASE 模拟实体与传感器，Cesium 提供当前的人机显示入口。任务编辑、方案审查和下发控制还需要继续接入，当前 Cesium 尚不是完整的交互式规划工具。

从本仓库的具体任务实现与示例看，现成任务库明显侧重**侦察、搜索与持续监视**：点／线／区域／模式搜索回答“去哪里看、怎样覆盖”，Watch／MultiVehicleWatch／Escort 回答“怎样持续观察已知目标或其附近”。后者基于实体状态开展规划，不代表已经接入图像目标检测与识别。盘旋、必经点、集结和通信中继属于通用行动或协同保障；地面通路封控等任务也说明其范围不只限于空中侦察。底层任务分配、顺序、路线和计划管理较通用，可为其他任务复用，但新任务仍需实现其动作、约束、代价、完成条件与仿真评估。当前项目已经验证的业务范围更集中：点、线、矩形搜索及相应执行／覆盖统计。

## 1. 当前正在复用的规划基础

| 能力 | 主要实现 | 可继续复用的内容 | 当前资格边界 |
| --- | --- | --- | --- |
| 请求校验与关联 | `AutomationRequestValidatorService` | 检查飞机、任务与运行区域输入，关联请求／响应 | 已用于真实初始化和规划；网页任务提交尚未开放 |
| 任务服务创建 | `TaskManagerService`、`TaskServiceBase` | 根据消息类型创建任务服务，复用候选方案、代价和任务实现接口 | 点／线／矩形链路已验证；新类型需逐项接入 |
| 路线与转场代价 | `RoutePlannerVisibilityService`、`RouteAggregatorService` | 起终点之间及任务之间的路线、候选飞机转场代价、分配代价矩阵 | 当前场景路线已运行；任意禁入区与复杂约束组合另验 |
| 任务分配与顺序 | `AssignmentTreeBranchBoundService` | 根据任务选项及代价，选择执行实体并安排任务顺序，处理任务关系表达 | 原两实体水道请求及当前固定分配均已使用；任意多机多任务自由分配组合未全面验收 |
| 完整计划组装 | `PlanBuilderService` | 连接转场和任务航点，为各飞机生成完整规划响应 | 已用于真实运行和完整规划显示 |
| 航点分段与续发 | `WaypointPlanManagerService` | 将完整计划分成命令段，依据实体执行进度继续发送 | 当前航点段与推进证据已验证 |
| 执行中的传感器动作 | 对应搜索任务服务及其执行逻辑 | 随飞机状态更新云台凝视位置等动作，使传感器服务于任务 | 当前搜索场景已验证；其他任务动作须独立核对 |

当前分配服务的公开代码按 `MINMAX` 计算：比较各飞机累计任务／转场预计时间的最大值。它主要优化所建模的执行代价，不直接最大化 AMASE 实飞覆盖率；复杂任务关系和其他代价模式不能只凭配置字段存在就视为已合格。

主要依据：[上游核心服务说明](../OpenUxAS/doc/reference/UserManual/Services/Services.tex)、[原水道服务配置](../OpenUxAS/examples/02_Example_WaterwaySearch/cfg_WaterwaySearch.xml)、[Windows 来源清单](../config/uxas-sources.json)、[服务注册](../OpenUxAS/src/cpp/Services/00_ServiceList.h)、[G3 阶段验收](g3-stage-validation.md)。

## 2. 可复用的任务类型

下面的“待接入”表示源码和相应示例存在，其在当前 Windows 后端、地形、网关和 Cesium 组合中的行为仍需验证。

| 任务类型 | 能力与适用输入 | 本项目现状 |
| --- | --- | --- |
| `PointSearchTask` 点搜索 | 观察一个指定地面位置 | CMASI 版本已验证；当前点统计为有效观察时间 |
| `LineSearchTask` 线搜索 | 观察道路、水道等地面折线，生成任务航线及传感器指向 | CMASI 版本已验证；完整水道保留 |
| `AreaSearchTask` 区域搜索 | 根据地面区域生成搜索航线 | 当前矩形任务已验证；圆形／多边形示例不能自动继承矩形资格 |
| IMPACT 点／线搜索 | 以独立 `PointOfInterest`／`LineOfInterest` 对象描述搜索目标 | 有对应实现，待接入；与 CMASI 同名类型要区分命名空间和字段 |
| `AngledAreaSearchTask` 指定方向区域搜索 | 在区域搜索中指定扫掠方向 | 待接入；可以作为后续可控扫掠方向的基础 |
| `PatternSearchTask` 模式搜索 | 围绕参考点生成 Spiral、Sector、Sweep 等搜索图样 | 源码包含螺旋、扇区和扫掠分支，待逐种验证 |
| `WatchTask` 持续监视 | 一架实体跟随并观察另一个实体，依据目标状态更新 | 对应实现名为 `OverwatchTaskService`，待接入；不是图像识别或自动发现未知目标 |
| `MultiVehicleWatchTask` 多机监视 | 多架实体共同跟随、观察指定实体 | 待接入，需验证多机行为和后端状态关联 |
| `EscortTask` 伴随侦察 | 相对移动实体的偏置位置进行观察，例如其前方或后方 | 待接入；任务语义侧重伴随观察，不包含完整作战护航裁决 |
| `LoiterTask` 盘旋 | 围绕指定位置执行盘旋任务 | 专门任务类型待接入；当前场景已有初始盘旋行为不等于此任务已经验收 |
| `MustFlyTask` 必经点 | 要求实体飞到指定点，可附加动作 | 待接入，可作为转场和必须访问位置的任务基础 |
| `RendezvousTask` 集结同步 | 让参与实体在同一时刻满足约定位置要求，使用等待／盘旋协调到达 | 待接入，需检查时间同步、位置和航向证据 |
| `CommRelayTask` 通信中继 | 规划用于通信中继支持的实体行为 | 待接入；不能据此宣称已验证真实无线信道、容量或全链路连通性 |
| `CordonTask` 区域通路封控 | 面向多地面车辆和区域进出路线的任务 | 后续地面系统方向；需要道路及相应规划资源，不是当前无人机显示场景能力 |
| `BlockadeTask` 多实体围控 | 安排多实体围绕指定实体的任务行为 | 待接入，不等于本项目已有完整对抗仿真 |

以上实现可在 [任务源码目录](../OpenUxAS/src/cpp/Tasks) 和 [任务示例目录](../OpenUxAS/examples/99_Tasks) 对照。较适合进一步阅读的说明有：[模式搜索](../OpenUxAS/examples/99_Tasks/PatternSearchTask/README.md)、[指定方向区域搜索](../OpenUxAS/examples/99_Tasks/AngledAreaSearchTask/README.md)、[持续监视](../OpenUxAS/examples/99_Tasks/WatchTask/README.md)、[伴随侦察](../OpenUxAS/examples/99_Tasks/EscortTask/README.md)、[集结同步](../OpenUxAS/examples/99_Tasks/RendezvousTask/README.md) 和 [通信中继](../OpenUxAS/examples/99_Tasks/CommRelayTask/README.md)。示例存在只作为功能设计依据，不作为本轮运行证明。

## 3. 路线和协同能力的具体边界

| 能力 | 能复用什么 | 仍需补齐或验证什么 |
| --- | --- | --- |
| 平面允许区／禁入区规划 | 可视图路线服务读取区域几何，为给定起终点生成二维路线 | 复杂边界、缓冲、飞机转弯后的完整路径、区域高度／时间语义须按具体场景验证 |
| 航向与转弯约束 | 当前路线服务使用飞机速度、最大滚转角等得到转弯参数，并处理需要指定的起终航向 | 不构成全包线飞行性能保证，也不是三维爬升／地形避障规划器 |
| 多机多任务排序 | 分支定界框架与任务关系处理已存在 | 当前三实体固定一机一任务；要展示自由分配，需调整候选资格与请求，并建立新验收 |
| 地面道路路线 | `OsmPlannerService` 提供 OSM 路网输入和地面路线／代价接口 | 需要合适路网和地面车辆配置；当前 `planet.pmtiles` 显示底图不能直接当作该规划器路网输入 |
| 分布式任务协同 | 存在 `AssignmentCoordinatorTaskService` 和上游分布式示例 | 当前 Windows 默认关闭 Zyre；通信配置、协同状态与故障恢复要另建资格 |
| 已知移动目标的任务更新 | 监视／伴随任务根据目标实体状态持续更新相关行为 | 要有可靠目标状态，不能等同于自主视觉识别、未知目标搜索与识别闭环 |

相关源码：[可视图路线服务](../OpenUxAS/src/cpp/Services/RoutePlannerVisibilityService.cpp)、[OSM 路线服务](../OpenUxAS/src/cpp/Services/OsmPlannerService.h)、[分配基础实现](../OpenUxAS/src/cpp/Services/AssignmentTreeBranchBoundBase.cpp)。动态多机防碰撞、三维地形避障、覆盖率自动寻优和学习策略不在当前已验证复用范围内。

## 4. 怎样在本项目中复用

当前最直接的复用方式是继续运行现有 UxAS 后端，通过消息调用其服务。现有发布形式是可执行程序和消息接口，并未把这些服务整体封装成供网页直接调用的独立 Python 库或控制 Web API。

1. **把用户意图转换为已有任务消息**：例如地图上的矩形形成 `AreaSearchTask`，选中的候选飞机形成资格和请求清单。
2. **补齐所需上下文**：实体性能／状态、传感器、任务引用的兴趣点／区域，以及运行区域等。只传一条任务名称不足以规划。
3. **保留当前的初始化检查和请求关联**：任务服务就绪后发送 `AutomationRequest`，接收相应规划响应和分配结果。
4. **按交互要求处理计划与执行**：当前航点管理链会自动把规划结果转为执行命令；若要“先预览、用户确认后执行”，必须增加明确的下发控制与身份绑定，不能把现有自动执行链直接当作纯预览接口。
5. **为新类型补完整业务支持**：检查网关投影、前端输入／几何／状态、后端完成语义以及相应统计。新任务不一定有“完成即结束”的语义，也不能默认套用点／线／区域覆盖口径。
6. **用真实场景验证**：确认计划、实际命令、飞行或车辆运动、传感器行为及统计相互一致，再登记该任务的组合资格。

原有点、线、矩形搜索和规划主链可以作为任务编辑界面的首批基础；随后可验证多候选飞机自由分配与多任务顺序，再按实际需要接入必经点、盘旋、模式搜索、监视、伴随和同步等。此为复用建议，不改变当前 T08 的实施顺序，也不将任务编辑自动并入 G6 仿真时间控制。

## 5. 当前优先保留的工程资产

- **保留规划后端和既有任务服务**：当前点、线、矩形任务已经完成真实执行验证，前端可集中处理任务输入与结果呈现。
- **保留消息模型与初始化机制**：延续 LMCP 定义、来源校验、请求／响应身份和就绪条件。
- **保留计划与执行的分离显示**：完整规划、当前命令、实际轨迹和执行证据仍分别呈现。
- **保留独立统计检查**：AMASE 任务统计用于检验实际效果，不能以规划器预计代价或一张覆盖示意图代替。
- **把缺失的交互与资格补在对应位置**：Cesium 任务编辑、规划请求接口、审查后下发、执行中重规划及新任务生命周期分别设计和验证。
